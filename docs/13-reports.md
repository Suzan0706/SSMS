# 13. Report Designs

## 13.1 Common layout

All reports have the same bilingual header and footer:

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ [logo]  SHULE YA SEKONDARI MFANO · S.L.P. 100, DODOMA · +255 754 000 000     │
│         <TITLE IN KISWAHILI> / <Title in English>                            │
│         Mwaka/Year: 2026   Muhula/Term: I   Imetolewa/Generated: 22/10/2026  │
├──────────────────────────────────────────────────────────────────────────────┤
│                               … body …                                       │
├──────────────────────────────────────────────────────────────────────────────┤
│ Imetolewa na/Generated by: registrar · Ref: RPT-8c1d…   Ukurasa/Page 1 of 3  │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **Language.** `lang=sw` puts Kiswahili first, `lang=en` puts English first; both are always printed in headings.
- **Formats.** Preview in the browser (first 100 rows); export to PDF (A4, WeasyPrint), Excel (openpyxl) or CSV. Exports over 2,000 rows run as a Celery job.
- **Money and dates.** Money is shown as `TZS 1,250,000`, dates as `dd/mm/yyyy`, times in EAT.
- **Audit.** Every export writes an `EXPORT` audit row with the report type and filters.
- **Database role.** Report SQL runs as the read-only database role `sms_reporting`. Parameters are written `:name`.

Every query below was executed against the sample data in [db/seed.sql](../db/seed.sql). The sample outputs are real results from that run.

## 13.2 Student list — *Orodha ya Wanafunzi*

| Item | Value |
|---|---|
| Users | Admin, Registrar, Bursar, Instructor (own classes) |
| Filters | academic year (current), level, stream, status, gender |
| Grouping | level → stream; totals by gender per stream |

```sql
-- Report: student list
SELECT cl.code                                         AS level,
       e.stream,
       st.admission_no,
       u.last_name || ', ' || u.first_name || COALESCE(' ' || u.middle_name, '') AS full_name,
       u.gender,
       date_part('year', age(u.date_of_birth))::int     AS age,
       st.current_status,
       g.phone                                         AS guardian_phone
FROM students st
JOIN users u                               ON u.user_id = st.user_id
LEFT JOIN v_student_current_enrolment e    ON e.student_id = st.student_id
LEFT JOIN class_levels cl                  ON cl.level_id = e.level_id
LEFT JOIN LATERAL (
    SELECT gu.phone
    FROM student_guardians sg
    JOIN guardians gd ON gd.guardian_id = sg.guardian_id
    JOIN users gu     ON gu.user_id = gd.user_id
    WHERE sg.student_id = st.student_id AND sg.is_primary
) g ON TRUE
WHERE st.current_status = 'ACTIVE'
ORDER BY cl.sort_order, e.stream, u.last_name, u.first_name;
```

## 13.3 Class schedule — *Ratiba ya Vipindi*

| Item | Value |
|---|---|
| Users | Everyone (students see their stream; instructors their own; room view for admin) |
| Filters | term + one of: offering & stream · instructor · room |
| Layout | Grid: rows = periods (08:00–14:20, with break and lunch rows), columns = Jumatatu…Ijumaa / Monday…Friday |

```sql
-- Report: class schedule (one class stream)
SELECT s.day_of_week,
       to_char(s.time_start, 'HH24:MI') || '-' || to_char(s.time_end, 'HH24:MI') AS period,
       sub.name_sw, sub.name_en,
       u.first_name || ' ' || u.last_name AS instructor,
       r.room_code
FROM schedules s
JOIN subjects sub   ON sub.subject_id   = s.subject_id
JOIN instructors i  ON i.instructor_id  = s.instructor_id
JOIN users u        ON u.user_id        = i.user_id
JOIN rooms r        ON r.room_id        = s.room_id
WHERE s.term_id = :term_id AND s.offering_id = :offering_id AND s.stream = :stream
ORDER BY s.time_start, s.day_of_week;
```

## 13.4 Enrolment report — *Ripoti ya Usajili*

| Item | Value |
|---|---|
| Users | Admin, Registrar |
| Filters | academic year, course, level, status, date range |
| Sections | (a) summary per offering with places left; (b) detail list of applications with document status |

```sql
-- Report: enrolment summary per offering
SELECT c.course_code,
       cl.code AS level,
       o.capacity,
       COUNT(e.enrolment_id) FILTER (WHERE e.status IN ('PENDING','SUBMITTED','INVALID','VALIDATED')) AS in_progress,
       COUNT(e.enrolment_id) FILTER (WHERE e.status = 'CONFIRMED') AS confirmed,
       COUNT(e.enrolment_id) FILTER (WHERE e.status = 'CANCELLED') AS cancelled,
       o.capacity - COUNT(e.enrolment_id) FILTER (WHERE e.status = 'CONFIRMED') AS places_left
FROM course_offerings o
JOIN courses c       ON c.course_id = o.course_id
JOIN class_levels cl ON cl.level_id = o.level_id
LEFT JOIN enrolments e ON e.offering_id = o.offering_id
WHERE o.academic_year_id = :academic_year_id
GROUP BY c.course_code, cl.code, cl.sort_order, o.capacity
ORDER BY cl.sort_order, c.course_code;

-- Report: enrolment detail (documents valid / required)
SELECT e.enrolment_no, st.admission_no, u.first_name || ' ' || u.last_name AS student,
       c.course_code, cl.code AS level, e.status, e.applied_at::date AS applied,
       COUNT(d.document_id) FILTER (WHERE d.status = 'VALID')   AS docs_valid,
       COUNT(d.document_id) FILTER (WHERE d.status = 'INVALID') AS docs_invalid,
       COUNT(d.document_id) FILTER (WHERE d.status = 'PENDING') AS docs_pending
FROM enrolments e
JOIN students st         ON st.student_id = e.student_id
JOIN users u             ON u.user_id = st.user_id
JOIN course_offerings o  ON o.offering_id = e.offering_id
JOIN courses c           ON c.course_id = o.course_id
JOIN class_levels cl     ON cl.level_id = o.level_id
LEFT JOIN enrolment_documents d ON d.enrolment_id = e.enrolment_id
WHERE o.academic_year_id = :academic_year_id
GROUP BY e.enrolment_id, st.admission_no, u.first_name, u.last_name, c.course_code, cl.code
ORDER BY e.applied_at;
```

## 13.5 Transaction history — *Historia ya Miamala*

| Item | Value |
|---|---|
| Users | Admin, Bursar (all); Student/Parent (own statement only, via `/students/{id}/statement`) |
| Filters | date range (EAT), student, payment method, type, status |
| Totals | per method (ROLLUP) and grand total of completed credits |

```sql
-- Report: transaction history
SELECT (t.trans_date AT TIME ZONE 'Africa/Dar_es_Salaam')::date AS date_eat,
       t.trans_no, st.admission_no,
       u.first_name || ' ' || u.last_name AS student,
       t.trans_type, t.payment_method, t.reference_no,
       CASE WHEN t.trans_type IN ('PAYMENT','WAIVER') THEN t.amount_tzs ELSE -t.amount_tzs END AS signed_amount_tzs,
       t.status, rb.username AS recorded_by
FROM transactions t
JOIN students st    ON st.student_id = t.student_id
JOIN users u        ON u.user_id = st.user_id
LEFT JOIN users rb  ON rb.user_id = t.recorded_by
WHERE t.trans_date >= :date_from AND t.trans_date < :date_to
ORDER BY t.trans_date;

-- Totals per payment method (completed only)
SELECT COALESCE(payment_method, 'TOTAL') AS method,
       SUM(CASE WHEN trans_type IN ('PAYMENT','WAIVER') THEN amount_tzs ELSE -amount_tzs END) AS amount_tzs,
       COUNT(*) AS transactions
FROM transactions
WHERE status = 'COMPLETED' AND trans_date >= :date_from AND trans_date < :date_to
GROUP BY ROLLUP (payment_method)
ORDER BY payment_method NULLS LAST;
```

## 13.6 Student status report — *Ripoti ya Hali za Wanafunzi*

| Item | Value |
|---|---|
| Users | Admin, Registrar |
| Filters | date range of `effective_date`, status, level |
| Sections | (a) current count per status; (b) every change in the period with reason and who made it |

```sql
-- (a) current counts
SELECT COALESCE(current_status, 'TOTAL') AS status, COUNT(*) AS students
FROM students
GROUP BY ROLLUP (current_status)
ORDER BY current_status NULLS LAST;

-- (b) changes in the period
SELECT h.effective_date, st.admission_no,
       u.first_name || ' ' || u.last_name AS student,
       h.old_status, h.new_status, h.reason, cb.username AS changed_by
FROM student_status_history h
JOIN students st   ON st.student_id = h.student_id
JOIN users u       ON u.user_id = st.user_id
LEFT JOIN users cb ON cb.user_id = h.changed_by
WHERE h.effective_date BETWEEN :date_from AND :date_to
ORDER BY h.effective_date, st.admission_no;
```

## 13.7 Report card — *Ripoti ya Maendeleo ya Mwanafunzi*

| Item | Value |
|---|---|
| Users | Admin, Academic Master, Class Teacher; Student/Parent (published only) |
| Filters | term, assessment type (MIDTERM / TERMINAL / ANNUAL), class stream or one student |
| Content | each subject: score, NECTA grade, points, remark; average; total points of the best *n* subjects (CSEE 7, ACSEE 3); division; position in stream; attendance %; class teacher's and head's comments |

```sql
-- Report: report card summary (one row per student) for a stream
WITH r AS (
    SELECT sr.*, e.offering_id, e.stream
    FROM v_student_results sr
    JOIN enrolments e ON e.enrolment_id = sr.enrolment_id
    WHERE sr.term_id = :term_id AND sr.assessment_type = :assessment_type AND sr.is_published
      AND e.offering_id = :offering_id AND e.stream = :stream
),
ranked AS (
    SELECT r.*, ROW_NUMBER() OVER (PARTITION BY r.student_id ORDER BY r.points, r.score DESC) AS rn
    FROM r
),
summary AS (
    SELECT ranked.student_id, ranked.exam_scale,
           ROUND(AVG(ranked.score), 2)                                          AS average,
           COUNT(*)                                                             AS subjects_sat,
           SUM(ranked.points) FILTER (WHERE ranked.rn <= es.best_n_subjects)    AS best_points,
           COUNT(*) >= es.best_n_subjects                                       AS complete
    FROM ranked
    JOIN exam_scales es ON es.exam_scale = ranked.exam_scale
    GROUP BY ranked.student_id, ranked.exam_scale, es.best_n_subjects
)
SELECT st.admission_no, u.first_name || ' ' || u.last_name AS student,
       s.average, s.subjects_sat, s.best_points,
       CASE WHEN s.complete THEN d.division ELSE 'INC' END AS division,
       RANK() OVER (ORDER BY s.average DESC) AS position
FROM summary s
JOIN students st ON st.student_id = s.student_id
JOIN users u     ON u.user_id = st.user_id
LEFT JOIN division_scales d
       ON d.exam_scale = s.exam_scale AND s.best_points BETWEEN d.min_points AND d.max_points
ORDER BY position;
```

`INC` (incomplete) is printed when a student sat fewer subjects than the division rule needs. The sample school has only 4 graded subjects, so both sample students show `INC`.
